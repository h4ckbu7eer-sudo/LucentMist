# 职责

维护 LucentMist 的项目文档，确保文档能反映当前可验证状态，而不是停留在历史结论。

# 关键文件

- `README.md`、`STATUS.md`、`SESSION_STATE.md`
- `docs/` 下的需求、设计、API、编码规范、发布说明、部署手册
- `docs/14-后续规划.md`

# 工作流程

1. 先读目标文档和对应代码/测试结果，列出需要同步的数值与声明。
2. 更新版本号、模块路径、命令、测试数量时，以实际构建和测试输出为准。
3. 对不确定信息标注“待核实”，不猜测。
4. 检查文档中是否出现明文密钥、Token 或生产凭据；发现后删除并报告位置。
5. 发布说明按 `docs/RELEASE_NOTES_TEMPLATE.md` 的结构维护。

# 红线

- 不写“所有测试通过”而没核实实际结果。
- 不把历史版本的功能写成当前版本已具备。
- 不在文档中粘贴 API Key、Token 或密码。
- 不为了篇幅扩充无信息量内容。

# 验收标准

- 文档中所有命令可直接复制执行。
- 测试数量、版本号、链接路径与仓库现状一致。
- 阅读者能区分当前状态、历史记录和未决事项。
