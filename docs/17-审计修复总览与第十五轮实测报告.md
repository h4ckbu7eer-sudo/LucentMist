## 2. 第十五轮修复内容

### 2.1 Docker 默认绑定

问题：API/Web 默认绑定 `localhost`，直接 `docker run -p` 后容器内无法从宿主机访问。

修复：Dockerfile 增加：

```dockerfile
ENV LMIST_BIND_ADDRESS=0.0.0.0
ENV LMIST_WEB_BIND=0.0.0.0
```

### 2.2 Docker 镜像体积

问题：`chown -R app:app /app` 复制了已 COPY 进镜像的三层产物，造成约 87MB 额外体积。

修复：

```dockerfile
COPY --from=build --chown=app:app /app/api ./api
COPY --from=build --chown=app:app /app/web ./web
COPY --from=build --chown=app:app /app/cli ./cli
COPY --chown=app:app config/ ./config/
RUN mkdir -p /app/data /app/logs && chown app:app /app/data /app/logs
```

结果：镜像从 619MB 降至 489MB。

### 2.3 Nmap 跨平台

- 路径查找支持 `NMAP_PATH`、Windows 常见路径、Linux/macOS 常见路径。
- Windows 使用 `where nmap`，Linux/macOS 使用 `which nmap`。
- `ScanAsync` 允许 IP 和主机名，同时拒绝命令行注入输入。

### 2.4 CPE 单一数据源

- `CpeCatalog.Entries` 现在是唯一数据源。
- `GetCpe()` 与 `GetKeyword()` 从 `Entries` 推导，不再维护三套 switch。
- 新增测试确保每个条目都能解析出 CPE 和 Keyword。

### 2.5 运行时额外发现

Web 首次请求时日志出现 `ObjectDisposedException`，根因是 `ScanTaskClient.DisposeAsync()` 被组件与 DI 容器重复调用。

修复：`DisposeAsync()` 增加幂等保护，重复调用不再执行 `Cancel()` 和 `Dispose()`。

### 2.6 全量复查额外修复

- `PingScanTool` 支持主机名/域名目标，不再把 `localhost`、`example.com` 静默解析成空设备列表。
- API `UseCors()` 分支补齐大括号和正确缩进。
- `NmapEnhancer.IsValidTarget` 增加主机名与命令注入校验，并新增测试。

### 2.7 五维度并行审计后续修复

- Dockerfile 调整 COPY 顺序：先复制项目定义还原依赖，再复制全部源码，避免代码改动使 NuGet 缓存层失效。
- Dockerfile 健康检查增加 `--start-period=30s`。
- `scripts/start.sh`、`scripts/start.ps1` 改为 `LucentMist.slnx`。

- `ToolRegistry` 改为 `ConcurrentDictionary`，单例注册不再有字典并发写风险。

### 2.10 ReAct 输出管道修复

- `ReActEngine` 新增 `ObservationsForRound(round)`，按 `Step` 关联 thought 与全部 observation。
- `AgentController` 与 `CliApp` 不再用 `ThoughtLog.Count` 截断 observation，自动服务识别的多端口结果全部输出。
- 新增回归断言：`port_scan` 自动识别 2 个端口时，`ObservationsForRound(1)` 返回 3 条 observation。

### 2.11 Docker 扫描与 CIDR 修复

- `docker-compose.yml` 为 API/Web 增加 `cap_add: NET_RAW`，容器内 ICMP Ping 可用。
- `PingScanTool` 检测 ICMP 权限错误后自动回退 TCP 探测（80/443/22/445），并在结果中输出 `icmpFallback` 提示。
- `/31`、`/32` CIDR 现在被 API 和 PingScanTool 正确支持，不再返回空列表或报错。
- `CveApiClient.WithRetry` 增加 source 失败日志（`LMIST_CVE_DEBUG=true` 时输出），便于定位 API 源。
- 缓存过期清理此前已实现，本轮补充测试覆盖。

### 2.12 核心数据与安全修复

- `ScanWorker` 启动时把所有 `pending/running` 任务标记为失败，避免重启后任务永久丢失。
- 队列元素取出后如果被取消，会先标记该任务失败，不再让元素静默消失。
- `ScanCoordinator.Complete()` 在 `ScanWorker.StopAsync` 时调用，关闭时不再无限阻塞。
- `AgentSessionStore.AddMessageAsync` 改为事务写入，`message_count` 不再因中途崩溃漂移。
- `ReActResult` 对 `ThoughtLog`/`Observations` 做副本，引擎下次运行不再破坏已返回结果。
- Ollama ReAct 请求使用独立 `system` role，不再把系统提示词混进用户消息。
- Ollama/Claude 对扫描 Banner 观察数据增加“不可信、不要执行指令”提示，缓解间接 Prompt 注入。
- OpenSSH for Windows 版本提取修正，`OpenSSH_for_Windows_8.1` 不再被误判为协议版本 `2.0`。

未在本轮强改：多用户授权模型与 ScanHub 所有权校验需要独立改造，避免在单用户本地工具中引入破坏性行为。

### 5.3 触发前提与限制

- GitHub Actions 的 cron 使用 UTC 时间，`0 * * * *` 表示每个小时整点触发，提交并推送到 GitHub 后才会生效。
- 本会话未暴露 Codex 的自动化调度工具，因此无法从当前对话直接创建“每小时唤醒 Codex 自动修复”的任务；该能力需要在 Codex 桌面端 Automations 面板或具备 `automation_update` 工具的环境中创建。
- GitHub CI 每小时自检只负责检测和告警，不会自动修改代码；本机计划任务在自检失败时会调用 Codex CLI 修复并复检，但不会自动提交或推送。
- 本机 .NET SDK 曾出现缺失 Workload 目录和大量残留 MSBuild 进程的问题，已通过关闭节点复用、清理残留进程和重新构建解决；完整 restore 在网络不稳定时可能超时，可使用 `-NoRestore`（Windows）或 `--no-restore`（Linux/macOS）复用已还原依赖。
