| **R2** | Ollama 模型损坏无法恢复 | 中 | 高 | 🔴 | 1.1.2 排查后模型仍需重拉 | 重新 `ollama pull llama3.1:8b`(4.9GB)；如网络慢，切换 qwen2.5:7b 验证；增加 Claude API 作为回退 provider 的自动切换逻辑 | 开发 |
| **R3** | CI GitHub API 401 无法解决 | 低 | 中 | 🟡 | 1.1.3 排查后仍 401 | 检查 `secrets.GITHUB_TOKEN` 权限范围；检查 repo Settings → Actions → Read and write permissions；如仍不工作，CI badge 改用静态 shield.io，Actions 状态通过本地截图替代 | 开发 |
| **R4** | rc1 发现 P0 阻塞性 bug | 低 | 高 | 🔴 | 回归测试发现新 P0 | bug 修复优先于功能开发；从 2.1.1 工时池调配，超过 6h 则延期 M5；P0 修复后再打 rc2 | 开发 |
| **R5** | Agent 回放页面开发超时 | 中 | 中 | 🟡 | 1.2.1 到 D4 未完成 | 缩小范围：仅做历史回放（只读），暂停/继续 和 时间线视图 降级到 v1.1.0 | PM |
| **R6** | 开发人力不可用（生病/紧急事务） | 低 | 高 | 🔴 | 开发请假 >1 天 | 所有里程碑顺延对应天数；PM 可执行纯文档/检查清单任务以降低阻塞；P2 任务批量移出 v1.0.0 范围 | PM |
| **R7** | Docker 构建在网络受限环境失败 | 低 | 低 | 🟢 | 用户报告 clone 后 docker build 失败 | 使用 `--build-arg NUGET_SOURCE` + restore 重试；提供预构建镜像作为 fallback | 开发 |
| **R8** | 依赖库出现严重 CVE | 低 | 中 | 🟡 | GitHub Dependabot 告警 Critical | 评估 CVE 是否影响本项目的依赖路径（ASP.NET / SQLite / System.Text.Json）；如在攻击面内则升级修复，否则记录豁免 | 开发 |

## 6. 需求变更管理规范

### 6.1 变更控制流程

```
                     ┌─────────────┐
                     │  提出变更    │
                     │  (任何人)    │
                     └──────┬──────┘
                            │
                     ┌──────▼──────┐
                     │  PM 初审     │
                     │  填写 CR 表  │
                     └──────┬──────┘
                            │
              ┌─────────────┼─────────────┐
              │             │             │
         ┌────▼────┐  ┌────▼────┐  ┌────▼────┐
         │ 拒绝     │  │ 延后    │  │ 接受     │
         │ (关单)   │  │ (标wontfix│  │ (排期)  │
         │          │  │  或vNext)│  │         │
         └──────────┘  └──────────┘  └────┬────┘
                                          │
                                   ┌──────▼──────┐
                                   │  PM + 开发  │
                                   │  估算工时    │
                                   └──────┬──────┘
                                          │
                                   ┌──────▼──────┐
                                   │  PM 签发     │
                                   │  更新 WBS    │
                                   │  通知干系人   │
                                   └─────────────┘
```

### 6.2 变更分级

| 级别 | 定义 | 示例 | 审批 | 是否影响排期 |
|------|------|------|:--:|:--:|
| **P0-阻塞** | 不修则不可发布 | 安全漏洞、数据丢失 | PM 即时审批 | 是 |
| **P1-重要** | 严重影响用户体验 | 核心功能不可用、CI 红 | PM 审批 | 评估后决定 |
| **P2-一般** | 锦上添花 | UI 微调、文案修改 | PM 周会审批 | 否（排 vNext） |
| **P3-建议** | 可做可不做 | 代码风格、重构建议 | 记录不排期 | 否 |
