## 为什么升级

0.9.7 标识 0.9.6 后的网关分析修复，不覆盖旧标签。升级前备份扫描数据；回滚可使用保留的 0.9.6 镜像及其发布说明中的摘要。

- 完成度检查允许有限但有用的安全评估；未知版本或一次失败不再要求无限补查。
- HTTP HEAD/GET 探测区分未公开版本与抓取失败；DNS 在同次 Agent 分析共享快照，不把多次请求当成同一观察。
- 老且无版本证据的云端 CVE 线索折叠；默认最多5条，原始工具数据保留，`-v` 查看详细过程。
- 端口断言按目标合并实际受检范围，识别任意1–65535数字端口及共享服务目录，不再只硬编码RDP/SSH等四项。未扫端口不等于未开放。
- DNS 单次响应比不作为低风险阈值；不因数值是2.1、0.1或20就声称安全。
- 精简模型结论后的工具事实补充，仍保留TLS信任错误、过期、来源和覆盖边界。

## 已知限制与部署

- 网关版本未知时只能给暴露面、TLS风险、线索与下一步，不是确认CVE，也不能宣称整体安全。
- 云源可能404/超时/限流；协议关键词搜索不是产品或版本匹配。
- DNS结论只适用于本次扫描源。容器内127.0.0.1是容器自身，不是Windows宿主机；容器网卡与宿主机网卡也不是同一视角。
- 断言守卫是带预算的防误导机制，不是对所有自然语言变体的形式化证明。原始扫描范围/错误/来源仍是证据。
- 生产/非回环部署必须设置强API和Web凭据，外部模型key只放受保护环境；本次验证使用隐藏stdin传入进程环境，不放Docker配置或命令参数。
- 扫描及报告含敏感网络数据，SQLite明文；按自用手册限制权限并备份。只扫描明确授权目标。
