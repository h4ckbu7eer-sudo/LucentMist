## 1. 部署方式

### 1.1 本地部署（开发/测试）

**步骤：**

```bash
# 1. 确认环境
dotnet --version  # 需要 10.0 SDK

# 2. 编译项目
cd /opt/LucentMist  # 或 E:\LucentMist
dotnet build -c Release

# 3. 发布
dotnet publish src/LucentMist.CLI -c Release -o publish/cli
dotnet publish src/LucentMist.API -c Release -o publish/api
dotnet publish src/LucentMist.Web -c Release -o publish/web

# 4. 运行
./publish/cli/lmist status
./publish/api/LucentMist.API
dotnet ./publish/web/LucentMist.Web.dll 5051
```

### 1.2 Docker 部署

镜像统一使用仓库根目录的 `Dockerfile`，多阶段构建：

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY LucentMist.slnx ./
COPY src ./src/
COPY . .
RUN dotnet restore src/LucentMist.API/LucentMist.API.csproj --configfile /tmp/NuGet.config
RUN dotnet publish src/LucentMist.API -c Release -o /app/api
RUN dotnet publish src/LucentMist.Web -c Release -o /app/web
RUN dotnet publish src/LucentMist.CLI -c Release -o /app/cli

FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
COPY --from=build /app/api ./api
COPY --from=build /app/web ./web
COPY --from=build /app/cli ./cli
EXPOSE 5050 5051
CMD ["dotnet", "api/LucentMist.API.dll"]
```

**构建与运行：**

启动前在未提交的 `.env` 或 secret manager 中设置强随机值：

```text
LMIST_API_TOKEN=<至少 32 字节随机值>
LMIST_WEB_USER=<非默认管理用户名>
LMIST_WEB_PASSWORD=<强随机密码>
```

`0.9.5` 会让 API/Web 容器复用共享 token 文件；留空自动生成只适用于隔离的本地演示。
生产环境仍必须显式设置三项强凭据。`0.9.4` 的空 token 协调缺陷及回滚要求保留在
[0.9.4 历史发布说明](RELEASE_0.9.4.md)中。

```bash
docker build --build-arg NUGET_SOURCE=https://repo.huaweicloud.com/repository/nuget/v3/index.json -t lucentmist:0.9.5 .
docker compose up -d

# API 健康检查
curl http://localhost:5050/api/v1/health

# Web 管理界面
curl http://localhost:5051/
```

若部署 GHCR 发布物而不是本地构建，私有包需要经典 PAT 的 `read:packages` 权限：

```bash
echo "$CR_PAT" | docker login ghcr.io -u YOUR_GITHUB_USER --password-stdin
docker pull ghcr.io/h4ckbu7eer-sudo/lucentmist:0.9.5
docker tag ghcr.io/h4ckbu7eer-sudo/lucentmist:0.9.5 lucentmist:0.9.5
docker compose up -d --no-build
```

正式发布说明记录经过验证的 manifest digest；生产和回滚应固定该摘要，避免版本标签被重新指向时悄悄改变部署内容。令牌只通过标准输入传给 Docker，不要提交到 `.env`、脚本或仓库。

国内网络构建时可指定华为云 NuGet 镜像；默认使用 `api.nuget.org`。Dockerfile 通过 `NUGET_SOURCE` 构建参数和 restore 重试保证依赖可恢复。

CLI 已发布到镜像 `/app/cli`，本机也可直接运行 `dotnet run --project src/LucentMist.CLI`。

### 1.3 systemd 服务（Linux）

```ini
# /etc/systemd/system/lucentmist-api.service
[Unit]
Description=LucentMist API Service
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/LucentMist
ExecStart=/opt/LucentMist/publish/api/LucentMist.API
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable lucentmist-api
sudo systemctl start lucentmist-api
```

## 2. 配置文件完整说明

### 2.1 配置文件位置

```
config/
├── appsettings.json           # 主配置文件
├── secrets.json               # 敏感信息（API Key 等，不提交 Git）
└── prompts/
    └── system_prompt.txt      # AI 系统提示词
```

### 2.2 环境变量覆盖

所有配置项均可通过环境变量覆盖：

```bash
# Linux/macOS
export LMIST_LLM_PROVIDER=claude
export LMIST_LLM_MODEL=claude-sonnet-4-6
export LMIST_LLM_ENDPOINT=http://localhost:11434
export LMIST_LLM_APIKEY=sk-ant-api03-xxx
export LMIST_DB=/app/data/lucentmist.db

# Windows
set LMIST_LLM_PROVIDER=claude
set LMIST_LLM_MODEL=claude-sonnet-4-6
set LMIST_LLM_APIKEY=sk-ant-api03-xxx
```

优先级：**环境变量是当前实现读取的配置源**；`secrets.json` 与 `appsettings.json` 不再被读取。

支持的变量：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `LMIST_LLM_PROVIDER` | `ollama` | `ollama` 或 `claude` |
| `LMIST_LLM_MODEL` | `qwen2.5:7b` | LLM 模型名 |
| `LMIST_LLM_ENDPOINT` | `http://localhost:11434` | Ollama 端点 |
| `LMIST_LLM_APIKEY` | 空 | Claude API Key |
| `LMIST_DB` | `data/lucentmist.db` | SQLite 数据库路径 |

### 2.3 安全配置建议

- **生产环境**：使用 `LMIST_LLM_APIKEY` 环境变量存储 API Key
- **开发环境**：Ollama 本地运行无需 API Key
- **API 鉴权**：必须设置强随机 `LMIST_API_TOKEN`，客户端在 Header 中携带 `Authorization: Bearer <token>`
- **Web 鉴权**：必须设置非默认 `LMIST_WEB_USER` 与强随机 `LMIST_WEB_PASSWORD`
- **密钥存储**：不要提交 `.env`；生产环境使用平台 secret manager

## 3. 日志管理

### 3.1 日志级别

| 级别 | 说明 | 适用场景 |
|------|------|----------|
| Debug | 详细信息 | 开发调试 |
| Information | 常规信息 | 生产默认 |
| Warning | 警告事件 | — |
| Error | 错误事件 | 排查问题 |

### 3.2 查看日志

```bash
# 文件日志
tail -f logs/lucentmist-api.log

# 控制台日志（开发环境）
DOTNET_ENVIRONMENT=Development dotnet run --project src/LucentMist.API

# 过滤特定级别
grep "ERROR" logs/lucentmist-api.log logs/lucentmist-web.log
```

### 3.3 日志轮转

日志文件位于 `logs/` 目录。建议配置日志轮转（logrotate 或 script）：

```
# /etc/logrotate.d/lucentmist
/opt/LucentMist/logs/*.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
```

## 4. 性能调优

### 4.1 扫描参数

| 工具参数 | 默认值 | 建议 |
|----------|--------|------|
| `PingScanTool: timeout_ms` | 3000 | 内网 1000-3000；外网可增至 5000 |
| `PingScanTool: concurrency` | 50 | 实测 50-200 均可用，建议 50-100 |
| `PortScanTool: timeout_ms` | 2000 | 建议 100-1000（实测 1000 端口并发 100 约 1.1s） |
| `PortScanTool: concurrency` | 100 | 建议 50-100 |
| `UdpScanTool: timeout_ms` | 3000 | 建议 1000-3000 |
| `UdpScanTool: concurrency` | 20 | 实测 5 即可覆盖 6 端口，建议 5-20 |

完整实测见 `docs/16-性能基准报告.md`。

### 4.2 Agent 参数

| 参数 | 当前实现 | 说明 |
|------|-----------|------|
| ReAct 最大轮数 | 5 | 在 API/CLI 中硬编码，暂未开放配置 |
| Ollama Temperature | 0.7 / 0.3 | 对话 0.7，ReAct 推理 0.3 |

### 4.3 资源最优配置

| 场景 | 并发 | 超时 | 模型 |
|------|------|------|------|
| 家庭网络 (< 50 设备) | 50 | 3000 | qwen2.5:3b |
| 小型办公室 (50-200) | 100 | 5000 | qwen2.5:7b |
| 大型网络 (200+) | 200 | 10000 | claude-sonnet-4-6 |

## 5. 数据存储

### 5.1 SQLite 数据库

```bash
# 数据库位置（默认）
data/lucentmist.db

# 备份
cp data/lucentmist.db data/lucentmist.db.backup.$(date +%Y%m%d)

# 恢复
cp data/lucentmist.db.backup.20260726 data/lucentmist.db

# 查看表结构
sqlite3 data/lucentmist.db ".tables"
sqlite3 data/lucentmist.db ".schema scan_tasks"
```

### 5.2 缓存

当前版本不依赖 Redis。扫描状态与 Agent 会话均持久化到 SQLite；本节保留仅用于历史部署排查。

### 5.3 备份策略

```bash
#!/bin/bash
# 每日备份脚本 backup.sh
BACKUP_DIR="/backup/lucentmist/$(date +%Y%m%d)"
mkdir -p "$BACKUP_DIR"

# 备份数据库
cp data/lucentmist.db "$BACKUP_DIR/"

# 备份配置
cp -r config "$BACKUP_DIR/"

# 保留最近 7 天
find /backup/lucentmist -maxdepth 1 -mtime +7 -exec rm -rf {} \;
```

## 7. 升级指南

### 7.1 升级步骤

```bash
# 1. 备份
cp -r config config.backup
cp data/lucentmist.db data/lucentmist.db.backup

# 2. 拉取新版本代码
git pull origin main

# 3. 编译
dotnet build -c Release

# 4. 发布
dotnet publish src/LucentMist.API -c Release -o publish/api

# 5. 重启服务
systemctl restart lucentmist-api  # systemd
# 或
docker restart lucent-mist         # Docker
```

### 7.2 回滚方案

```bash
# 1. 恢复备份
cp -r config.backup/* config/
cp data/lucentmist.db.backup data/lucentmist.db

# 2. 切换到旧版本
git checkout v0.0.X

# 3. 重新编译部署
dotnet publish -c Release -o publish/api
systemctl restart lucentmist-api
```

### 7.3 数据库迁移

当前版本数据库结构不变，跨版本升级一般无需迁移。如遇新版本有 schema 变更：

```bash
# 备份数据库后
sqlite3 data/lucentmist.db < migrations/v0.2.0_up.sql
```

## Web 管理界面部署

### 本地启动

```bash
dotnet run --project src/LucentMist.Web
# 默认 http://localhost:5051
```

### Docker 部署

```bash
docker compose up -d
# Web 默认 http://localhost:5051
```

### 自定义端口

```bash
dotnet run --project src/LucentMist.Web -- 8080
```

### 生产环境建议

- 使用 Nginx 反向代理 + HTTPS
- 配置 `ASPNETCORE_ENVIRONMENT=Production`
- 限制 SignalR 连接数 (`builder.Services.AddSignalR(o => o.MaximumReceiveMessageSize = 64KB)`)
