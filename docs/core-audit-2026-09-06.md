## 性能证据与取舍

- 相同产品/版本、两次分析（80/443）：受控 HTTP handler 计数从 **6 次降到 3 次**，减少 50% 重复请求。
  这是请求计数，不是声称真实互联网扫描提速两倍。
- 完整快照缓存 600 秒，部分失败缓存 30 秒，最多 256 个键；命中标明“缓存，非本轮重新查询”。
- 设备补查保持最多 3 台并行；已有扫描 worker 小并发池和监控设备并发限制保留。
- 这里只缓存第三方漏洞元数据，不缓存目标端口探测，不用缓存掩盖真实设备变化。

- 本轮没有重新调用真实 DeepSeek，没有重新扫描真实网关/公网主机，没有验证手机实际入网。
  本机 TCP/HTTP 与故障注入不能代替这些实机验证；上一轮真实监控证据仍见 [监控验收记录](home-monitor-validation.md)。
- 未执行本批远端 push、CI/GHCR 发布验证；仅作本地逻辑独立提交。
- 目标不公开软件版本时仍不能确认具体 CVE；厂商 OUI 不等于设备型号；UDP 重置/不可达仍是平台层推断。

- 恢复前仍须停止 API/Web/monitor；验证的是进程内文件移动失败的可恢复性，不保证断电时多文件替换的原子性。
