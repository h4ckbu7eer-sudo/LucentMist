## 1. 产品简介

### 1.1 LucentMist 是什么

LucentMist 是一个**智能网络分析助手**。它把网络扫描引擎和大型语言模型（LLM）结合起来，让你用自然语言就能分析和探索网络。

不需要记住 `nmap -sS -p 1-1000 192.168.1.0/24` 这样的命令，直接说"帮我看下家里网络有哪些设备"，AI 就会自动完成扫描和分析。

### 1.2 核心能力

| 能力 | 说明 | 示例 |
|------|------|------|
| 设备发现 | ICMP Ping 扫描局域网，找到所有在线设备 | `scan 192.168.0.0/24` |
| TCP 端口扫描 | TCP Connect 模式扫描 1-65535 端口 | 自动发现 22(SSH)、80(HTTP) 等 |
| UDP 端口扫描 | UDP 探测 DNS/SNMP/NTP 等 11 种服务 | `scan --udp 192.168.1.1` |
| SSL 证书校验 | 获取 SSL/TLS 证书，检查有效期 | `ssl-check example.com` |
| 服务识别 | Banner 抓取，判断端口上跑的是什么服务 | 识别 nginx、OpenSSH、MySQL |
| AI 推理 | ReAct 模式：思考 → 行动 → 观察 → 回答 | "分析我的网络安全" |
| 双 LLM | 本地 Ollama（隐私）或 Claude API（强推理） | 配置切换 |

### 1.3 适用场景

- 家庭网络管理：了解家里连了多少设备、哪些设备有异常端口
- 小型办公室运维：快速扫描办公网络，检查服务器服务状态
- 安全自查：检查是否有未授权设备接入，开放端口是否符合预期
- 学习网络技术：通过 AI 对话理解扫描结果，学习网络知识

## 2. 系统要求

### 2.1 硬件要求

| 组件 | 最低配置 | 推荐配置 | 说明 |
|------|----------|----------|------|
| CPU | 双核 1.5GHz | 四核 2.0GHz+ | 端口扫描大量 IP 时 CPU 密集 |
| 内存 | 512 MB | 2 GB+ | Agent 模式需要更多 |
| 磁盘 | 50 MB（程序） | 10 GB+（含模型） | llama3.1:8b 约 5GB |
| 网络 | 可访问局域网 | 有线连接 | WiFi 扫描速度慢于有线 |

### 2.2 软件要求

| 软件 | 版本 | 必需 | 说明 |
|------|------|:--:|------|
| .NET SDK | 8.0 | 是 | 编译和运行 |
| Ollama | 最新版 | 否 | 本地 AI 推理（Agent 功能需要） |
| 推荐模型 | llama3.1:8b | 否 | 约 4.9 GB，需 6GB+ 显存 |

### 2.3 平台兼容性

| 操作系统 | 扫描 | Agent | API | 备注 |
|----------|:----:|:-----:|:---:|------|
| Windows 10/11 | 完全支持 | 完全支持 | 完全支持 | TCP 扫描无需管理员 |
| Ubuntu 20.04+ | 完全支持 | 完全支持 | 完全支持 | — |
| macOS 12+ | 完全支持 | 完全支持 | 完全支持 | ICMP 可能受限 |

## 3. 安装步骤

### 3.1 从源码编译（通用方式）

```bash
# Step 1: 进入项目目录
cd E:\LucentMist
# 或 Linux/macOS: cd /opt/LucentMist

# Step 2: 还原 NuGet 依赖包
dotnet restore
# 首次运行会下载约 200MB 依赖，需要几分钟

# Step 3: 编译所有项目
dotnet build
# 预期输出: 已成功生成。0 个警告 0 个错误

# Step 4: 运行测试验证安装
dotnet test
# 预期输出: 通过! 13/13

# Step 5: 验证 CLI
dotnet run --project src/LucentMist.CLI -- status
# 预期输出: 版本信息表格
```

### 3.2 配置本地 AI（Ollama）

Agent 功能需要 Ollama 提供本地 AI 推理。

```bash
# Step 1: 确认 Ollama 已安装并正在运行
# Windows: 双击 Ollama 托盘图标，或命令行启动
ollama serve
# 默认监听 http://localhost:11434

# Step 2: 下载推荐模型（首次约需 5-10 分钟）
ollama pull llama3.1:8b
# 下载到 E:\Ollama\models\ 或其他安装目录

# Step 3: 验证模型可用
ollama list
# 应显示: llama3.1:8b  4.9 GB

# Step 4: 测试模型能正常回复
ollama run llama3.1:8b "hello"
```

### 3.3 配置 Claude API（备选）

如果不想本地跑模型，或者本地性能不够：

```bash
# 1. 获取 API Key: https://console.anthropic.com/
# 2. 编辑 config/appsettings.json
{
  "LucentMist": {
    "LLM": {
      "Provider": "claude",
      "Model": "claude-sonnet-4-6",
      "ClaudeApiKey": "sk-ant-api03-xxxxxxxxxxxxx"
    }
  }
}
```

### 3.4 安装后验证

```bash
# 测试扫描（本机）
dotnet run --project src/LucentMist.CLI -- scan 127.0.0.1
# 预期: 发现 1 台设备 (127.0.0.1)

# 测试 Agent（确保 Ollama 在运行）
dotnet run --project src/LucentMist.CLI -- agent "扫描127.0.0.1的端口"
# 预期: AI 自动调用 port_scan，返回开放端口列表
```

## 4. 配置文件详解

### 4.1 配置文件位置

```
config/
  appsettings.json          # 主配置文件（可提交 Git）
  secrets.json              # 密钥文件（不提交 Git，可选）
  prompts/
    system_prompt.txt       # AI 系统提示词
```

配置文件优先级（从高到低）：
1. 环境变量 `LucentMist__{Section}__{Key}`
2. `secrets.json`
3. `appsettings.json`

### 4.2 完整配置项说明

```json
{
  "LucentMist": {

    // ===== LLM 配置 =====
    "LLM": {
      // Provider 类型: "ollama" 或 "claude"
      "Provider": "ollama",

      // 模型名称。
      // Ollama: 用 "ollama list" 查看已下载模型
      // Claude: "claude-sonnet-4-6" | "claude-opus-4-8" | "claude-haiku-4-5"
      "Model": "llama3.1:8b",

      // Ollama 服务地址（仅 Provider=ollama 时生效）
      "OllamaEndpoint": "http://localhost:11434",

      // Claude API Key（仅 Provider=claude 时生效）
      // 获取地址: https://console.anthropic.com/settings/keys
      "ClaudeApiKey": "",

      // Claude 模型名（备用，通常留空使用 Model 字段）
      "ClaudeModel": "claude-sonnet-4-6",

      // 单次生成最大 Token 数。大值 = 长回复
      "MaxTokens": 4096,

      // 生成随机性: 0.0=精确固定, 1.0=创意发散
      // 扫描分析建议 0.3-0.5，闲聊建议 0.7-1.0
      "Temperature": 0.7
    },

    // ===== Agent 配置 =====
    "Agent": {
      // ReAct 最大循环轮次。超过后强制终止
      // 简单任务 3-5 轮，复杂分析 8-15 轮
      "ReActMaxRounds": 10,

      // 系统提示词文件路径（相对于项目根目录）
      "SystemPromptFile": "config/prompts/system_prompt.txt",

      // Agent 会话超时时间（分钟）
      "SessionTimeoutMinutes": 30
    },

    // ===== 扫描配置 =====
    "Scan": {
      // 单次连接默认超时（毫秒）
      // 局域网 2000-3000ms，WiFi 5000ms，远程 10000ms
      "DefaultTimeoutMs": 5000,

      // 最大并发连接数。太高可能触发防火墙
      "MaxConcurrency": 100,

      // 默认扫描端口范围
      "DefaultPorts": "1-1000",

      // 每秒最大发包数（防止被当成攻击）
      "RateLimitPerSecond": 50
    },

    // ===== 数据库配置 =====
    "Database": {
      // SQLite 数据库文件路径
      "SQLitePath": "data/lucentmist.db",

      // Redis 连接串。留空则使用内存存储
      "RedisConnection": "localhost:6379"
    },

    // ===== API 服务配置 =====
    "API": {
      // 监听端口
      "Port": 5050,

      // Bearer Token 鉴权。留空则不启用认证
      "AuthToken": ""
    },

    // ===== 日志配置 =====
    "Logging": {
      // 日志级别: Debug | Information | Warning | Error
      "Level": "Information",

      // 日志文件路径。控制台始终输出
      "FilePath": "logs/lucentmist.log"
    }
  }
}
```

### 5.2 scan — 网络扫描

**用途**：扫描指定网段，发现在线设备和开放端口。

**语法**：
```bash
dotnet run --project src/LucentMist.CLI -- scan <target>
```

**参数**：

| 参数 | 格式 | 示例 | 说明 |
|------|------|------|------|
| target | IP 或 CIDR | `192.168.1.1` | 单 IP |
| | | `192.168.1.0/24` | C 段（254 个 IP） |
| | | `10.0.0.0/28` | 小范围（14 个 IP） |

**执行逻辑**：
1. 解析 CIDR → 生成 IP 列表
2. 对每个 IP 发送 ICMP Ping（并发，默认 50 并发）
3. 收集在线设备列表
4. 对前 3 台在线设备执行常用端口扫描（22,80,443,3389,8080,8443）
5. 输出结果表格

**示例**：

```bash
# 扫描 192.168.56.0/24 网段
dotnet run --project src/LucentMist.CLI -- scan 192.168.56.0/24
```

**输出示例**：
```text
 扫描目标: 192.168.56.0/24

 ┌────────────┬──────┐
 │ 项目       │ 数值 │
 ├────────────┼──────┤
 │ 扫描 IP 数 │ 254  │
 │ 在线设备数 │ 2    │
 └────────────┴──────┘

   192.168.56.46
   192.168.56.231
 耗时: 4.2s
```

### 5.2.1 UDP 端口扫描

**用途**：通过 UDP 协议探测目标设备的 UDP 服务端口。UDP 是无连接协议，通过发送协议特定的探测包并等待响应来判断端口是否开放。

**语法**：
```bash
dotnet run --project src/LucentMist.CLI -- scan <target> --udp [--ports <ports>]
```

**参数**：

| 参数 | 格式 | 默认值 | 说明 |
|------|------|--------|------|
| target | IP | (必需) | 目标 IP 地址 |
| --ports | 逗号/范围 | `53,123,161,500,514,1900` | 支持 `53,123` 或 `67-69` 或 `53,67-69,161` |
| --timeout-ms | 毫秒 | 3000 | 每个端口超时 |
| --concurrency | 数字 | 20 | 并发探测数 |

**支持的 UDP 服务**：

| 端口 | 服务 | 端口 | 服务 |
|------|------|------|------|
| 53 | DNS | 123 | NTP |
| 67-68 | DHCP | 137 | NetBIOS-NS |
| 69 | TFTP | 161 | SNMP |
| 500 | IKE (IPSec) | 514 | Syslog |
| 1900 | SSDP | 5353 | mDNS |

**示例**：
```bash
# 默认扫描常见 UDP 端口
dotnet run --project src/LucentMist.CLI -- scan 192.168.1.1 --udp

# 自定义端口
dotnet run --project src/LucentMist.CLI -- scan 192.168.1.1 --udp --ports 53,123,5353

# 端口范围
dotnet run --project src/LucentMist.CLI -- scan 192.168.1.1 --udp --ports 1-100
```

**注意事项**：
- UDP 扫描比 TCP 慢，因为需要等待超时确认端口关闭
- 防火墙可能会丢弃 UDP 包导致误判为"开放"（实际是 filtered）
- 建议针对特定已知 UDP 服务端口扫描，避免全范围扫描

### 5.2.2 SSL 证书校验

**用途**：连接目标 HTTPS 端口，获取 SSL/TLS 证书并检查有效期、SAN、证书链。

**语法**：
```bash
dotnet run --project src/LucentMist.CLI -- ssl-check <target> [--port <port>] [--timeout-ms <ms>]
```

**参数**：

| 参数 | 格式 | 默认值 | 说明 |
|------|------|--------|------|
| target | 域名/IP | (必需) | 目标地址 |
| --port | 数字 | 443 | SSL/TLS 端口 |
| --timeout-ms | 毫秒 | 5000 | 连接超时 |

**输出信息**：
- 颁发者（Issuer）
- 主题（Subject）
- 有效期（NotBefore / NotAfter）
- 剩余天数（DaysRemaining）
- 是否过期（IsExpired）
- 主题备用名称（SAN）— DNS 名称和 IP
- SHA-1 / SHA-256 指纹
- 证书链

**示例**：
```bash
# 检查百度证书
dotnet run --project src/LucentMist.CLI -- ssl-check baidu.com

# 指定端口
dotnet run --project src/LucentMist.CLI -- ssl-check example.com --port 8443
```

**输出示例**：
```text
 目标: baidu.com:443
 ├── 主题: CN=*.baidu.com
 ├── 颁发者: CN=GlobalSign RSA OV SSL CA 2018
 ├── 有效期: 2025-07-01 ~ 2026-08-02
 ├── 剩余天数: 368 天
 ├── 状态: ✅ 有效
 ├── SAN: *.baidu.com, baidu.com, *.baidu.cn
 └── 证书链: 3 级
```

### 5.3 agent — AI 智能体对话

**用途**：用自然语言与 AI 交互，AI 自动调用扫描工具并分析结果。

**语法**：
```bash
dotnet run --project src/LucentMist.CLI -- agent "<你的问题>"
```

**前提条件**：Ollama 必须运行，llama3.1:8b 模型已下载。

**执行流程**：

```
用户问题 → LLM 推理 → 选择工具 → 执行扫描 → 观察结果 → LLM 再推理 → ... → 最终答案
```

每轮循环：
1. LLM 分析当前状态，决定下一步
2. 如果需要数据 → 调用 ping_scan / port_scan / service_identify
3. 获取真实扫描结果 → 反馈给 LLM
4. 如果信息足够 → 输出结论（final_answer）
5. 如果信息不够 → 继续下一轮（最多 5 轮）

**示例**：

```bash
# 分析整个子网
dotnet run --project src/LucentMist.CLI -- agent "分析192.168.56.0/24的网络"

# 扫描特定设备
dotnet run --project src/LucentMist.CLI -- agent "看看192.168.56.231这台设备开了哪些服务"

# 安全评估
dotnet run --project src/LucentMist.CLI -- agent "检查我的网络有没有异常开放的端口"
```

**输出示例**：
```text

  模型    llama3.1:8b @ Ollama (localhost:11434)
  工具    ping_scan / port_scan / service_identify / device_query
  问题    看看192.168.56.231这台设备开了哪些服务

────────────────────── 推理过程 ──────────────────────
  [1]  需要扫描目标设备的端口，使用 port_scan
       -> port_scan
       目标     192.168.56.231
       扫描     1024 个端口
       开放     1 个端口
┌──────┬──────┐
│ 端口 │ 服务 │
├──────┼──────┤
│   53 │ DNS  │
└──────┴──────┘

  [2]  已获得端口信息，53端口是DNS服务，可以给出结论
       -> final_answer

┌─ 分析结论 ────────────────────────┐
│ 192.168.56.231 开放了 1 个端口：  │
│                                  │
│ 53 (DNS) - 域名解析服务          │
│                                  │
│ 该设备是网络中的DNS服务器或网关， │
│ 仅提供域名解析功能，未发现其他    │

└──────────────────────────────────┘
```

## 6. Agent AI 使用指南

### 6.1 工作原理

LucentMist Agent 基于 **ReAct（Reasoning + Acting）模式**：

```
   ┌──────────┐     ┌──────────┐     ┌──────────┐
   │ THOUGHT  │────>│  ACTION  │────>│OBSERVE   │
   │ (推理)   │     │ (行动)   │     │ (观察)   │
   └──────────┘     └──────────┘     └──────────┘
         ^                                  │
         └──────────────────────────────────┘
                   (循环直到有足够信息)
```

这不是简单的"问 → 答"模式。AI 会：
1. 分析你的问题，判断需要什么数据
2. 主动调用扫描工具获取真实数据
3. 根据实际结果继续推理
4. 最终给出基于事实的结论

### 6.2 可用工具

Agent 可以自主选择调用以下 4 个工具：

| 工具 | 功能 | 参数 |
|------|------|------|
| `ping_scan` | 探测子网存活设备 | `target`: 子网或 IP |
| `port_scan` | 扫描端口开放情况 | `target`, `ports`(范围) |
| `service_identify` | 识别端口服务类型 | `target`, `port` |
| `device_query` | 查询已发现设备 | `ip` 或 `type` |

### 6.3 使用技巧

**好的提问**（具体、明确）：
```
"扫描192.168.56.0/24，列出所有在线设备"
"检查192.168.56.231开放了哪些端口"
"分析网关设备的安全性"
```

**不好的提问**（模糊、范围太大）：
```
"扫一下网络"     → 不知道扫哪个网段
"安全吗"         → 没有目标
"帮我看看"       → 看什么？
```

### 6.4 推荐模型配置

| 模型 | 推荐度 | 大小 | 特点 | 场景 |
|------|:------:|------|------|------|
| **qwen2.5:7b** | ⭐⭐⭐⭐⭐ | ~4.5 GB | 中文理解优秀，JSON 稳定 | **首选推荐** |
| llama3.1:8b | ⭐⭐⭐⭐ | ~4.9 GB | 英文好，推理能力强 | 通用场景 |
| mistral:7b | ⭐⭐⭐ | ~4.1 GB | 速度最快，中文一般 | 低延迟需求 |
| claude-sonnet-4-6 | ⭐⭐⭐⭐⭐ | 云端 | 推理最强 | 需要 API Key |
| moondream:latest | ⭐ | 1.7 GB | 视觉模型 | 不适合 ReAct |

下载模型：

### 6.5 常见问题速查

| 现象 | 原因 | 解决 |
|------|------|------|
| 一直转圈不输出 | 模型首次加载到显存 | 等 30-120 秒 |

## 8. 输出结果解读

### 8.1 存活扫描输出

```
┌────────────┬──────┐
│ 项目       │ 数值 │
├────────────┼──────┤
│ 扫描 IP 数 │ 254  │  ← 子网内所有 IP
│ 在线设备数 │ 2    │  ← 响应了 ICMP 的设备数
└────────────┴──────┘

   192.168.56.46     ← 你的电脑
   192.168.56.231    ← 网关/路由器
```

- `total` = 2^(32-CIDR前缀) - 2（去掉网络地址和广播地址）
- `alive` = 实际响应了 Ping 的设备数
- 设备数 = 0 → 检查网段是否正确、防火墙是否拦截 ICMP

### 8.2 端口扫描输出

```
┌──────┬──────────┐
│ 端口 │ 服务     │
├──────┼──────────┤
│   53 │ DNS      │  ← UDP 53 → 域名解析
│   80 │ HTTP     │  ← Web 服务
│  443 │ HTTPS    │  ← 加密 Web
│   22 │ SSH      │  ← 远程登录
│ 3389 │ 远程桌面 │  ← Windows RDP
└──────┴──────────┘
```

常见端口含义：

| 端口 | 服务 | 说明 |
|------|------|------|
| 22 | SSH | Linux 远程管理 |
| 53 | DNS | 域名解析 |
| 80 | HTTP | Web 服务 |
| 135 | RPC | Windows 远程过程调用 |
| 443 | HTTPS | 加密 Web |
| 445 | SMB | Windows 文件共享 |
| 3389 | RDP | Windows 远程桌面 |
| 8080 | HTTP 代理 | 常见于路由器管理 |

### 8.3 Agent 输出结构

Agent 输出分三部分：

1. **头部面板**：显示模型、工具列表、你的问题
2. **推理过程**：每轮显示 `[轮次] 思考 → 工具名 → 结果表格`
3. **分析结论**：绿色面板包裹的最终答案

## 9. 故障排查

### 9.1 扫描无结果

**现象**：`在线设备数 0`

**排查步骤**：
```bash
# 1. 确认网络连通
ping 8.8.8.8

# 2. 检查自己的 IP 和子网
ipconfig  # 找到 IPv4 地址
# 例: 192.168.56.46, 掩码 255.255.255.0 → 子网 192.168.56.0/24

# 3. 用正确的子网扫描
dotnet run --project src/LucentMist.CLI -- scan 192.168.56.0/24

# 4. 测试本机（一定能通）
dotnet run --project src/LucentMist.CLI -- scan 127.0.0.1

# 5. 如本机能通但局域网不通 → 防火墙或路由器拦截 ICMP
```

### 9.2 Agent 不工作

**现象**：Agent 命令提示错误或超时

```bash
# 1. 确认 Ollama 在运行
curl http://localhost:11434/api/tags
# 有 JSON 输出 = 在运行

# 2. 确认模型已下载
ollama list
# 应有 llama3.1:8b

# 3. 确认模型能正常回复
ollama run llama3.1:8b "hello"
# 第一次回复需要加载模型（30-120 秒），之后很快

# 4. 如果 Ollama 没运行，启动它
# E:\Ollama\ollama serve
ollama serve
```

### 9.3 dotnet build 编译失败

```bash
# 检查 .NET 版本
dotnet --version
# 需要 >= 8.0.0

# 若版本不对，下载 .NET 8.0 SDK
# https://dotnet.microsoft.com/download/dotnet/8.0

# 清理后重建
dotnet clean
dotnet restore
dotnet build

# 查看具体错误
dotnet build --verbosity detailed
```

### 9.4 端口扫描慢

单个 IP 扫描 1024 端口约需 20-30 秒（TCP Connect 模式，每个端口需要三次握手）。

**加速方法**：
- 减少端口范围：只扫描常用端口 `"ports":"22,80,443,3389,8080"`
- 扫描本机 127.0.0.1（不需要经过网络栈）
- 增大并发数（编辑 appsettings.json → `MaxConcurrency` 改为 200）

### 9.5 性能参考数据

| 操作 | 耗时 | 说明 |
|------|------|------|
| 单 IP Ping | < 0.1s | 本机 |
| /24 Ping（254 IP） | 3-10s | 并发 50 |
| 单 IP 1024 端口扫描 | 20-30s | TCP Connect |
| 单 IP 6 端口扫描 | 1-3s | 常用端口 |
| LLM 首次推理 | 30-120s | 加载 4.9GB 模型 |
| LLM 后续推理 | 2-10s | 模型已在显存 |
